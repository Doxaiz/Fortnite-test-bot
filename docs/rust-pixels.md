# Пиксельные сканы: Rust и AutoHotkey

`native/pixels` — `cdylib` для Windows x64 без внешних Rust-крейтов. `pixel_backend.ahk` подключает её при запуске или при первом скане, в том числе при разборе сохранённого BMP. Скрипт ищет `forma_pixels.dll` только по полному пути рядом с `FORMA.exe` (в режиме исходников — рядом с `fortnite_bot.ahk`). Для поиска зависимостей DLL используется `LOAD_LIBRARY_SEARCH_SYSTEM32`. DLL загружается в процесс FORMA, не в Fortnite. Используйте DLL из того же проверенного ZIP, что и EXE.

В «Проверке запуска» и `run.log` отдельно указаны `Пиксельные сканы` и `Боевой скан`: `Rust DLL (ABI 1)` означает, что соответствующие функции загружены, `AutoHotkey (резерв)` — что работает AHK. ABI не менялся. Если у DLL нет боевых экспортов, нативное ускорение остаётся только у общих пиксельных сканов. Если есть тёплая сетка и движение, но нет нового `forma_pixels_warm_grid_peak`, сетка читается из DLL, а максимум 3×3 считается на AHK. Если конкретный запрос превышает лимит нативного скана или отклонён, он выполняется целиком на AHK, без смешивания результатов. Замена DLL требует перезапуска. Профиль не меняется.

## Что вынесено

| Rust | Что остаётся на AutoHotkey |
| --- | --- |
| Цветовая маска по одной или нескольким категориям и склейка 8-связных ячеек | ROI, настройки цвета, сортировка и выбор подходящей кнопки или объекта |
| Максимальная серия в каждой строке: жёлтая, светлая, светлая/лавандовая или красная | Склейка строк, размеры плашки, проверка текста и фона, выбор действия |
| Количество светлых/тёмных пикселей на сетке с шагом 4 | Порог яркости, деление и условия использования результата |
| Число тёплых проб на ячейку; первый максимум окна 3×3 в порядке строк; RGB-разница двух кадров, ячейки локального движения и отсечка широкого изменения | Выбор геометрии сеток, склейка движения, рамки, фильтры фигуры, сравнение метаданных кадров, подтверждение и ввод |

Кадры BGRX читаются без копирования, сверху вниз, с переданным `stride` в байтах. X-байт игнорируется. ROI — полуоткрытые целочисленные координаты; преобразование из долей кадра остаётся в AHK. ABI использует структуры `#[repr(C)]`, числа `u32` / `i32` и `usize` для длин. Версия, размеры и смещения полей проверяются тестами. Вызывающая сторона владеет буферами и держит их живыми во время синхронного вызова; DLL не сохраняет указатели и не меняет кадр. Возврат неотрицательного числа означает успех (число записей или совпадений), отрицательного — отклонённый запрос. Частичный выход при ошибке не используется.

Rust проверяет размеры, `stride`, размер буфера, область, параметры и ёмкость выхода. Лимиты: до 8192 px по стороне, 128 МиБ на кадр, 262 144 выборки на вызов и отдельный лимит на ячейки масок. Строковые сканы и доли яркости идут полосами до 32 выборочных строк; `TickCheck` остаётся до и после вызовов. Это ограничивает объём работы без точек прерывания, но не гарантирует срок выполнения. Боевые запросы используют тот же лимит выборок и до 131 072 ячеек на запрос. Дополнительный экспорт тёплой сетки записывает после ячеек три `u32`: столбец и строку верхнего левого угла (от 1) и сумму максимума 3×3. Если попаданий меньше трёх или нет полного окна, все три поля равны нулю. Переносятся только первичные измерения; захват, свежесть кадра и окна, сторож, весь ввод и чтение подсказки E остаются на AHK.

## Проверка

```powershell
# Из корня репозитория. Для тестов только Rust не нужен рабочий стол.
cargo test --locked --offline --manifest-path native/pixels/Cargo.toml
.\tools\build-portable.ps1 -SmokeTest
```

В Windows CI `dumpbin` проверяет, что у DLL только системные импорты (C runtime линкуется статически). Затем тесты сравнивают геометрию, порядок, число точек, доли и серии на одних и тех же буферах, запускают общие наборы с DLL и без неё, проверяют запуск и обновление из ZIP. Обязательный запуск с DLL не может пройти на AHK. Отдельные сценарии проверяют работу без DLL и с повреждённым файлом, даже если в другом рабочем каталоге лежит исправная DLL.

В логе сборки `-SmokeTest` и в аннотациях Windows CI есть сравнение `--bench-menu` (`FrameMenu`) и `--bench-combat` (`FindEnemyMulti`). Замеры обоих бэкендов выполняются на одинаковых синтетических буферах 720p и 1080p: два прогрева и 11 замеров на сценарий. Проверяется результат полного детектора без переиспользования его результата. Это время конкретных детекторов на машине CI, без захвата и игры, а не FPS или задержка полного тика. [Сценарии боевого замера](combat-scan.md).

Чтобы проверить DLL с исходным `.ahk`, соберите её отдельно и поместите рядом со скриптом:

```powershell
cargo build --locked --offline --release --target x86_64-pc-windows-msvc --manifest-path native/pixels/Cargo.toml
Copy-Item .\native\pixels\target\x86_64-pc-windows-msvc\release\forma_pixels.dll .
$ahk = "$env:ProgramFiles\AutoHotkey\v2\AutoHotkey64.exe"
Start-Process $ahk -ArgumentList '/ErrorStdOut=UTF-8 tests\native_pixels.ahk' -NoNewWindow -Wait
```

Локальная DLL и файлы сборки Cargo не входят в Git.
