# Выпуск FORMA для Windows

[На главную](../README.md) · [Сборка на Windows](guide.md#сборка-переносимого-exe)

[Portable Windows build](https://github.com/Doxaiz/Fortnite-test-bot/actions/workflows/portable.yml) собирает и проверяет переносимый ZIP в pull request, на `main`, на тегах `vX.Y.Z` и вручную. Обычные прогоны только сохраняют артефакт (14 дней). Для новых выпусков не нужно добавлять ZIP в Git: пользователи скачивают файлы из **Assets** релиза.

## Подготовка и проверка черновика

1. Установите согласованные `FORMA_VERSION` и `Ahk2Exe-SetVersion` в `fortnite_bot.ahk` (`X.Y.Z` и `X.Y.Z.0`). `-ExpectedTag vX.Y.Z` останавливает сборку **до загрузки зависимостей**, если версия не совпадает. Без заданного тега CI отдельно проверяет отказ на неверном номере.
2. После зелёных проверок проверьте точный SHA коммита в `main`. Создайте стабильный **черновик** `vX.Y.Z` с целью на этот SHA, а не на плавающую ветку:
   ```bash
   gh release create vX.Y.Z --draft --target COMMIT_SHA --title 'FORMA vX.Y.Z' --notes-file release-notes.md
   ```
3. Запустите **Portable Windows build → Run workflow** на `main` с `expected_tag: vX.Y.Z` и включите `stage_draft`. Windows собирает ZIP, прогоняет тесты, запускает EXE из ZIP и сохраняет артефакт. Следующий job берёт файлы **из этого же прогона**, сверяет обе суммы и целостность ZIP, загружает только недостающие вложения в черновик на проверенном SHA и скачивает их обратно для побайтового сравнения. Несовпадающие вложения не заменяются. На ветках PR запись в релизы не выполняется.
4. Дождитесь зелёного шага **Stage and verify the draft assets**. В черновике должны быть ровно три файла: `FORMA-vX.Y.Z-windows-x64.zip`, `AutoHotkey-v…-source.zip` и `SHA256SUMS.txt`. Напишите, что проверено на тестовых окнах и чего не подтверждает запуск EXE. Опубликуйте вручную и проверьте, что **Latest** показывает новый тег, а скачиваемые файлы совпадают с проверенными.

Если `stage_draft` не нужен, скачайте артефакт обычного прогона на нужном SHA и прикрепите все три файла из него вручную после проверки сумм. Не смешивайте файлы разных сборок: ZIP двух прогонов на одном коммите не обязан совпадать побайтно. При ошибке стадирования оставьте черновик неопубликованным; не удаляйте работающую загрузку прежнего выпуска.

`Attach portable assets` — отдельный инструмент только для старого формата, где ZIP и `SHA256SUMS.txt` уже находятся в `portable/` в соответствующем теге. Он проверяет существующий **Latest**, не создаёт выпуск и не заменяет несовпадающие файлы. Для новых выпусков используйте черновик и `stage_draft`, как описано выше.
