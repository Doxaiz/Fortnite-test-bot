# F5 по сохранённому BMP: сравнение с ONNX

`tools/replay_f5.ahk` повторно строит **тот же отчёт F5** из BMP, который сохранил Ctrl+F5. Он вызывает `BuildCalibrationReport` из FORMA, не дублируя правила поиска. Fortnite и окно FORMA не нужны. Скрипт не запускает захват, хоткеи или рабочий цикл, не отправляет ввод и не меняет исходный BMP/TXT. Python и модель для этого отчёта не нужны.

## Как повторить на своём кадре

В DryRun сохраните **Ctrl+F5**. Из корня репозитория в PowerShell (замените путь к AutoHotkey, если он установлен иначе):

```powershell
$ahk = "$env:ProgramFiles\AutoHotkey\v2\AutoHotkey64.exe"
$bmp = Get-ChildItem "$env:TEMP\FORMA-diagnostics" -File -Filter *.bmp |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
if (-not $bmp) { throw 'Сначала сохраните кадр Ctrl+F5' }
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
& $ahk '/ErrorStdOut=UTF-8' '.\tools\replay_f5.ahk' $bmp.FullName | Out-Host
```

Можно указать до **32 файлов** подряд. При повреждённом или неизвестном BMP сообщение идёт в stderr, следующие файлы всё равно проверяются, а код выхода не нулевой. Принимается исходный формат Ctrl+F5: 32-битный несжатый BMP сверху вниз (BGRX, 54-байтный заголовок, стороны 2–8192 px, не более 128 МиБ пикселей). Не пересохраняйте его в редакторе перед проверкой.

**Сохраните исходный TXT.** Новый отчёт использует настройки текущей сборки по умолчанию, без `forma.ini` и без динамического увеличения шага. Он не восстанавливает источник, время или параметры оригинального захвата. Строка `фигура: нет` — только результат статического скана; причины `маска тёплых пикселей или форма` недостаточно, чтобы узнать, какой именно фильтр отказал. В частности, `0%` может означать, что скан не дошёл до подсчёта плотности. Плашка E, HUD и другие строки отчёта — тоже наблюдения на одном кадре, не разрешение на действие.

## Что получилось на одинаковых пикселях

**40 опубликованных снимков**: все 26 из [первого прогона ONNX](enemy-vision.md#что-получилось-на-опубликованных-кадрах) и 14 файлов из [разбора ещё 29 снимков](enemy-vision-examples.md), для которых повторно получили те же копии. PNG/JPEG декодировали в BGR и записали без изменения размера и ориентации в BMP формата Ctrl+F5; после чтения BMP проверили равенство BGR. Оба скана получили эти же файлы. Тест выполнен с AHK v2.0.18 x64/Wine 7.0, FORMA v11.0.9 с настройками сборки, и прежней проверенной ONNX на CPU (ONNX Runtime 1.22.1, порог `0.25`, NMS `0.45`). Никаких новых весов, порогов или настроек рабочего цикла.

| Была ли хотя бы одна рамка | Файлов |
| --- | ---: |
| F5 и ONNX | 2 |
| Только F5 | 3 |

F5 вернул **5 рамок**, ONNX — **29** на 23 снимках. Это **не точность**: направления поиска отличаются, в счёт входят свои персонажи, фон и интерфейс. F5 проверяет центральную область и возвращает до одной статической фигуры; ONNX смотрит всё изображение и может вернуть несколько. Так же **не проверялись** локальное движение, очередность кадров, захват игрового окна или действия.

На **всех пяти** F5 не подтвердил HUD матча. Это сравнение **строки отчёта**, а не проверка, что рабочий цикл выбрал бы действие. И наоборот, неподтверждённый HUD старого или обрезанного кадра сам по себе не означает «это меню».
