# Поиск фигур со статичным прицелом (FORMA)

## Отсечка плотного фона (v11.0.9)

У прежнего поиска рамка росла по суммам по **всей** строке и столбцу. Яркая поверхность в стороне могла растянуть рамку другого объекта и занизить его плотность. Теперь для уже выбранной рамки верхний порог проверяется ещё раз по её локальной тёплой маске: пустые края не идут в знаменатель, внутренние пробелы остаются, шаг выборки и обрезка по ROI учитываются. Это только отказ по плотности: геометрия прошедшей рамки не меняется и другая тёплая область не подставляется. После отказа работает прежний локальный скан движения. F5 показывает `рамка растянута фоном` и процент без пустых краёв.

На [опубликованном кадре с коллиматором](https://github.com/slyautomation/yolov8/blob/f3cd1eacafd849af02547ae97d7d285a68d88332/fortnite_test_1.png) (1920×829) v11.0.8 поставила рамку `398,99,168,516` на оранжевой опоре. В рамке было **56%** тёплых проб; в локальной области высотой 408 px — **72%**, выше того же порога **68%**. v11.0.9 не выдаёт рамку на опоре, но **по одному этому кадру фигуру в прицеле всё ещё не видит**. На остальных 35 сочетаниях девяти архивных изображений и четырёх наборов области/шага результат не изменился; в том числе на `7455.png` с увеличенным шагом +4 осталась ложная рамка на фоне. Это проверка регрессии, а не оценка точности.

В синтетических парах 720p и 1080p тёплая опора остаётся одинаковой, прицел статичен, рядом появляется серая фигура. До правки статический бокс перекрывал движение, после отсечки найден тот же бокс движения, что и без опоры. Без фигуры боевая рамка не появляется; подтверждение E работает отдельно. На тестовом окне GDI проверены отсутствие рамки на опоре, первый и повторный замеры движения в F3, причина в F5 и виртуальная очередь в DryRun без системных нажатий. Проверки окна, возраста кадра, камеры, второго замера и «Команды» не ослаблены.

## Цвет прицела и локальное движение (с v11.0.8)

- **Прицел может быть любого постоянного цвета.** Цвет у центра больше не создаёт рамку цели, не заменяет второе наблюдение и не отбирает кадр у подсказки E. Отметка центра в F3 фиксированная. Слабый признак светлого центра в проверке HUD не связан с боем.
- **Движение разбирается локально.** В v11.0.7 все изменившиеся точки попадали в одну рамку: удалённая вспышка раздувала её, и продолговатый объект отбрасывался. В v11.0.8 соседние пробы собираются в отдельные группы. Скан учитывает контраст **изменившихся** пикселей в текущем кадре, а не неподвижную точку прицела внутри рамки. При распределённом изменении фона в нескольких частях кадра локальная цель не выбирается. Это не компенсация ручного поворота камеры.
- В **F3 «Зрение»** голубая рамка и строка `первый: …` означают один замер, красная рамка и `повтор: …` — кандидат повторился. Рамки показываются на том кадре, где они найдены. `Бой не сканировался` не означает, что игроков нет: ветке мог не достаться бюджет, кадр мог перейти к E или цикл мог ещё не войти в матч. Диагностика F5 показывает одиночный поиск фигуры, причину отказа и не оценивает движение.
- Две похожие проверки на разных свежих кадрах всё ещё обязательны. Для действий по кадру сохраняется предел **250 мс от начала захвата**, текущие окно, камера и поколение ввода. Режим «Команда» оставляет бой человеку. Цвет одежды, геометрия и локальная разница кадров **не различают надёжно игрока, союзника и фон**. Неподвижную фигуру без подходящего тёплого контура встроенный скан может не увидеть.

Два сценария воспроизводятся на v11.0.7: неподвижное красное пятно вызывает виртуальную очередь, а отдельная дальняя вспышка скрывает движущийся объект. Новые проверки проходят под AutoHotkey 2.0.18 x64/Wine 7.0, в том числе захват тестового окна с неизменным красным прицелом до появления фигуры и после её исчезновения. Оба случая до исправления проявлялись на фикстурах; живой матч не запускался.

## Проверка неподвижных фигур по снимкам (необязательно)

`tools/inspect_figures.py` ищет фигуры на уже сохранённых BMP/PNG/JPEG. Подходит прежняя одноклассовая ONNX FORMA (**вход 640×640, выход `(1,5,8400)`**). Модель не поставляется, не скачивается и в AHK не запускается. Скрипт читает только указанные файлы, не захватывает окно, не отправляет кадры, не управляет движением и не разрешает огонь.

1. В DryRun нажмите **Ctrl+F5** на игровом кадре. Пара файлов находится в `%TEMP%\FORMA-diagnostics`. Сохраните также один кадр той же сцены без видимого игрока, если это возможно.
2. Если у вас остались проверенные `forma_model\runtime-v1\fortnite.onnx` и Python с OpenCV/NumPy из прежней установки, можно запустить проверку этим Python. Если библиотек нет, создайте отдельное окружение Python 3.10–3.13. Для обычного запуска AHK этого не нужно:

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install 'numpy==2.2.6' 'opencv-python-headless==4.11.0.86'
   ```

3. Из корня репозитория выберите сохранённый BMP (в примере — последний) и запустите:

   ```powershell
   $shot = Get-ChildItem "$env:TEMP\FORMA-diagnostics" -Filter *.bmp |
       Sort-Object LastWriteTime -Descending | Select-Object -First 1
   if (-not $shot) { throw 'Сначала сохраните кадр Ctrl+F5' }
   .\.venv\Scripts\python.exe tools\inspect_figures.py $shot.FullName --view third-person --out .\figure-check
   ```

   Для своего доверенного `best.onnx` добавьте `--model <путь> --sha256 <ожидаемый-SHA-256>`. Две известные хэш-суммы прежней установки поддерживаются без `--sha256`. Сумма подтверждает только совпадение байтов; не загружайте неизвестные веса. `.pt` не поддерживается. `--out` создаёт отдельные PNG, не перезаписывая файлы; если они уже есть, выберите новую папку. Ни исходный BMP, ни отчёт AHK не меняются. Без `--out` выводится только JSON с рамками и `scan_ms`; `score` — оценка модели, а не вероятность, что это враг.

### Как читать рамки

`--view third-person` добавляет подсказки для вида от третьего лица. Для кадра через оптику используйте `--view scope`, для карты/инвентаря — `--view interface`. Если вид неизвестен, `--view unknown` ищет только признак метки союзника. Указанный вид применяется ко всем кадрам команды, **сам скрипт его не определяет**. Без `--view` остаются прежние рамки и прежний формат JSON.

- `ally-marker` / **ally marker?** — над рамкой есть признаки белой стрелки вниз и отдельной бирюзовой полосы, похожей на ник. Только бирюзового пятна недостаточно; слитый бело-голубой блик не считается парой. Маленькая жёлтая рамка отмечает найденную стрелку. Другие варианты HUD, в том числе ник вплотную к стрелке, могут остаться без подсказки.
- `own-area` / **own area?** — крупная рамка перекрывает типичную зону своего персонажа. Близкий другой игрок тоже может попасть в эту область. В режимах `scope` и `unknown` такой отметки нет.
- `interface-view` / **interface** — пользователь указал кадр интерфейса; найденные боксы остаются видимыми для диагностики.
- `unclassified` / **figure?** — нет этих подсказок. Это может быть другой игрок, союзник без видимой метки или декорация. **Это не метка врага.**

Ни одна подсказка не удаляет рамку и не меняет её координаты или оценку. Цвет прицела не нужен ни в одном из вариантов. Поиск в AHK и окно F3 остаются прежними.

### Необязательный CPU-бэкенд ONNX Runtime

OpenCV остаётся по умолчанию. Чтобы прогнать тот же кадр через ONNX Runtime, установите пакет в то же отдельное окружение и задайте `--backend onnxruntime`:

```powershell
.\.venv\Scripts\python.exe -m pip install 'onnxruntime==1.22.1'
.\.venv\Scripts\python.exe tools\inspect_figures.py $shot.FullName --view third-person --backend onnxruntime --out .\figure-check-ort
```

Этот бэкенд использует CPU и тот же подтверждённый по SHA-256 ONNX, параметры подготовки изображения и разбора рамок. Нужны один вход `float32 (1,3,640,640)` и один выход `float32 (1,5,8400)`. Пакет не нужен для OpenCV или обычного запуска FORMA.

Ложные рамки остались: например, на [кадре `19869`](https://github.com/Nathan-W-C/Fortnite-Object-Detection/blob/a2eb1f6fea9c06b99b37e926e7ffab2d7e33aded/test/19869.png) бокс `42,342,60,135` похож на ствол дерева и остаётся `unclassified`. Поднять порог недостаточно: можно оставить свой аватар и потерять небольшую фигуру. Четыре компактные модели из той же подборки были быстрее, но ни одна не сохранила все четыре видимые фигуры на первых трёх снимках. Эти модели не добавлены в FORMA.

На **26 архивных снимках** два бэкенда дали одинаковые координаты и порядок **18 рамок**, разница оценки не больше `0.00001` в выводе. На этом Linux CPU/OpenCV 4.11 медиана по 25 кадрам после первого — **302 мс**, с ONNX Runtime 1.22.1 — **160 мс** даже с `--view unknown`. `scan_ms` включает подготовку, вычисление рамок и подсказок, но не загрузку модели, чтение входа и запись PNG. Это один офлайн-прогон, не замер задержки Windows или живой игры. Небольшая выборка не даёт метрик «враг/свой». Модель **не подключена к вводу**.

В [отдельном разборе ещё 29 снимков](enemy-vision-examples.md) показаны находки, пропуски, ложные рамки на фоне и интерфейсе, а также сравнение полного кадра с центральной обрезкой. По одному из них исправили ложную подсказку `ally-marker` на бело-голубом блике; рамки и оценки не менялись.

Тесты инструмента без игровых кадров и весов, в том же окружении:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_inspect_figures.py
```

## Сравнение F5 и ONNX на одном файле

[`tools/replay_f5.ahk`](f5-replay.md) читает BMP из Ctrl+F5 и вызывает тот же построитель отчёта, что и F5, не запуская FORMA. В [сравнении на 40 одинаковых снимках](f5-replay.md#что-получилось-на-одинаковых-пикселях) оба метода увидели персонажа на лестнице, но F5 также принял вспышку и часть стены за фигуру, а ONNX дал рамку на нарисованной стрелке. Это сравнение статических результатов, не проверка действий по кадру.

## Что прислать для проверки вашей сцены

Лучше всего: **пара BMP+TXT с видимым противником и пара без него**, тот же режим, масштаб HUD и разрешение. Укажите примерное место фигуры на первом BMP. Для пропуска в движении полезны два соседних кадра либо короткая запись с неподвижной камерой: один снимок не проверяет движение. Также пригодятся строка запуска v11.0.9 и близкие записи `[combat-late]` / `[perf]`. Перед отправкой проверьте, что кадр не раскрывает личные данные. Если ONNX нет, никакие веса для отправки кадров не нужны.
